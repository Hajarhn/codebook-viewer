About this codebook
PCNN variable dictionary — researcher view

The PCNN Codebook is the variable dictionary for the Post-COVID Network Netherlands, a national collaborative research initiative funded by ZonMw. It documents the validated questionnaires used across PCNN sub-studies (PROMIS-29, DSQ family, EQ-5D-5L, COMPASS-31, Pain DETECT, SF-36, and others) and supports FAIR (Findable, Accessible, Interoperable, Reusable) data alignment across the network.

This is the researcher view of the codebook — read-only, with 9 curated fields. Use the "Suggest" button on any row to propose a change to the administrator.

🔒 Copyrighted questionnaires (PROMIS, EQ-5D, and others) are shown as placeholders. Contact the codebook owner for access to the full item list.

Built by Hajar Hasannejadasl — Maastricht University Medical Centre+ (MUMC+). Developed within the Post-COVID Network Netherlands (PCNN), funded by ZonMw.

Copyright protection

Many validated questionnaires are copyrighted (e.g. EQ-5D-5L, PROMIS-29). To track this in the codebook, add a copyright_status field to each variable. Recognized values:
  • "public" — freely shareable
  • "restricted" — copyrighted; not shown in restricted Excel exports
  • "licensed" — copyrighted but licensed for your use; treated as public
  • (empty / anything else) — treated as restricted by default
When "Respect copyright" is enabled during Excel export, restricted instruments are replaced with a single placeholder row showing the contact email below. This is a convention, not a security boundary — anyone with the source JSON sees everything.
Used as default in the Excel export dialog. Stored only in this session.

Auto-tracking

Every change you Apply automatically updates:
  • checked_by — your name appended (semicolon-separated if there were prior entries)
  • check_date — set to today's date (older dates kept after a "→")
  • change_log — append-only history: YYYY-MM-DD | name | field: "old" → "new"
The change_log field is created automatically the first time a variable is edited.

Notes & tips

  • Edits save to the cloud database automatically — there is no local file to keep.
  • Deleted variables go to Trash (Admin menu) and can be restored; other changes are kept in the Log (audit trail).
  • Multiple people can work at the same time. If two edit the same variable, the second save is warned before it overwrites the first.
  • Roles control who can do what: admin (full), editor (edit), ontology_engineer (granted fields), researcher (read + suggest changes).
  • Use Export Excel or Save JSON for a point-in-time backup before big changes.
  • Browser cache may serve a stale version — hard-refresh if the version number doesn't match.
